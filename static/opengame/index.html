01 / THE TECH

First, separate the model from the game.

Think of a simple request: “Make a game where I fly to a planet, land, and look for a lost object.” There are several ways AI can help—and they do not produce the same thing.

A

Write the game

Prompt → code → engine → play

A coding agent writes movement, cameras, scores and interfaces. The engine is the software that runs the rules and draws the result. Once built, a conventional game does not need the coding model to decide every frame.

Example: Void Explorer’s flight and landing.

B

Build its world

Prompt → 3D assets → engine → play

A model makes the environment or objects. Developers then add rules and interactions. A beautiful room is not yet a game: it needs such things as solid walls, usable doors and a reason to explore.

Example: Marble scenery in ICARE.

C

Generate as you play

Frames + action → model → next frames

An interactive world model synthesizes the next view from context and player input. It can invent a place without first assembling a normal game project. Long memory, exact rules and shared multiplayer state are much harder requirements.

Example: Google’s Project Genie.

Architectural synthesis from the linked implementations. A product can combine these approaches. Thomas Ricouard / OpenAI ↗World Labs + WithLore ↗Google DeepMind ↗

The AI helped write the program. During play, a game engine reads an explicit record. Returning to the room does not require a model to guess what happened. Bugs are still possible; this is a mechanism for consistency, not a promise of perfect software.

Now add another player. Both players must agree on the door, the score and who won. Shared state and synchronization are additional engineering jobs. This schematic teaches architectures; it is not a live AI demo or a claim about OpenGame’s implementation.

Why “the models got better” really matters

The useful unit of progress is a completed loop. Can the system understand an idea, change several related files, run the result, see what broke and repair it without losing the original intent?

Imagine the ship sinks through the planet. A text-only assistant can suggest a collision formula. An agent with tools can inspect the code, reproduce the landing, read the coordinates, change the collision logic and try again. That is a much larger reduction in work than faster autocomplete.

The harness is everything around the model that makes that loop work: tools, project context, saved versions, tests and feedback. A strong model inside a weak harness may still produce a fragile game. A good harness gives the model the right evidence and lets the creator recover when a change goes wrong.

SEPTEMBER / MODEL PROGRESS

Longer tasks, fewer lost threads.

Anthropic’s Fable 5.1 release emphasizes sustained coding and verification. Its launch includes Canva’s report of building a rhythm game with music and on-beat play. That is vendor-published customer testimony, not proof of a polished commercial release.

The mechanism: timing, audio and input need to work together. A better model can coordinate more of that interdependent work before the creator has to intervene. Anthropic’s release ↗

SEPTEMBER 10 / PRODUCT PROGRESS

The workflow lasts beyond one chat.

Cursor Projects adds a coordinator that delegates work, keeps shared project context and runs cloud agents after the laptop closes. It launched as a beta rollout.

The mechanism: remembering the project and running work over time are product capabilities around the model. They can help a creator maintain a growing game, but do not themselves guarantee good game design. Cursor’s release ↗

A test can prove “the door opens.”

It cannot by itself prove “opening this door feels satisfying.” Response time, sound, anticipation and difficulty are part of game design. Faster implementation gives a creator more chances to tune them; it does not automatically supply taste.

02 / THE PEOPLE

Meet the people crossing the old barriers.

These examples show different kinds of progress: a professional can work with a smaller team; a domain expert can become a creator; a designer can build beyond their technical background.

01

Damian Pannell

25 years in game art and direction

The experienced director, now working solo.

7–8 weeksto an approved Steam page, maker-reported

After roughly ten prototypes in Rosebud, Pannell chose Hollow Signal: an arcade roguelike with manual directional shooting. He used different models for simple and difficult changes, and added debug controls to jump directly to bosses. Steam confirms a July 14 release.

What you learn. AI reduces the distance between taste and implementation. His advantage includes knowing which prototype deserves another week—and which ones to abandon.

What this result does—and does not—prove

A released game is a concrete result. The store had just one visible review at research time; commercial demand is not established.

The model gets “hands” inside the engine.

Roblox reported that 44% of its top 1,000 creators used Assistant or third-party AI through MCP during March 6–April 7. That is any such use among a cohort ranked by Robux spent inside their games—not 44% of all developers, or of fully AI-made games.

Its agentic workflow plans and edits; automated playtesting was introduced in beta. Unity’s May open beta similarly lets an agent inspect scenes and work with scripts, components and prefabs.

MCP is a standard way to connect a model to tools. It gives the model access to the project and actions; it does not itself improve the model’s intelligence.

Roblox’s Cube workflow connects geometry to a behavior contract. The February beta started with Car-5 and Body-1 schemas, not arbitrary functional objects. In Wish Master, people generate objects while playing; the developer reported over 160,000 objects and 64% longer average playtime among generation users.

That playtime difference is correlational: enthusiastic players may be more likely to generate in the first place. Still, it illustrates a new product idea. The act of creation can be the entertainment, rather than work done before entertainment begins.

For OpenGame, there are two different customers.

The person making a game needs speed, control and repair. The person playing needs a good time, friends and something worth returning to. A shared platform must serve both—and help good creations find the right players.

04 / THE FRONTIER

When the model becomes part of the world.

This is the most visually astonishing part of the market. It is also where a short video can most easily suggest a more complete product than actually exists.

RESEARCH → LIMITED PRODUCT

Genie: an imagined place you can navigate.

Genie 3’s August 2025 research showed generated worlds at 720p and 24 frames per second, with interaction lasting a few minutes. Project Genie’s January 2026 US launch offered eligible adult AI Ultra subscribers a browser prototype for creating, exploring and remixing worlds.

The public prototype capped generations at 60 seconds and acknowledged control latency and imperfect physics. Model capability and product availability are different things. These are dated launch limits, not a claim that improvement stops there.

SEPTEMBER 1 / EARLY ACCESS

Atlas: give the model actual spatial context.

World Labs’ new model takes images, video, camera positions and depth. In its cottage demonstration, one photo leaves much of the scene imagined; adding photos constrains the reconstruction.

It can output precisely controlled views and explicit 3D representations, including Gaussian splats. The announcement shows up to one-minute, 1440p videos. Atlas is in select-partner early access and is intended to power future Marble versions; it is not the same as the already available Marble workflow.

THE BUG THAT EXPLAINS THE CATEGORY

Look at the floor. Look back. Where did the enemy go?

Microsoft’s April 2025 WHAMM Quake II demo used just 0.9 seconds of context. The researchers described enemies disappearing or changing when a player looked away; health and damage were also unreliable. It was progress in responsive generation—640 × 360 at over 10 fps—but not a faithful implementation of Quake’s rules.

Keep this distinction: a world can look convincing without having reliable memory. Newer approaches are improving memory; the example explains the engineering problem rather than defining every current model’s limit. Microsoft Research ↗

The practical middle path is already useful.

José Tijerín’s Gaussian Mansion starts with artwork, uses Marble to generate persistent environments, then integrates them into an Unreal Engine rail-shooter pilot. He still tunes scene overlap, rendering and interactions. World Labs + José Tijerín ↗

Rosebud’s multiplayer Simon Says demonstration follows the same logic: generated scenery, separate collision geometry, and templates supplying controls and synchronized objectives. Manual export and setup were still part of its November 2025 workflow. World Labs + Rosebud ↗

The design lesson is useful: ask which properties need to be exact. Let generation provide visual richness, while explicit software keeps the score, rules and shared state dependable.

A second distinction: restyling vs simulation.

Decart’s Oasis 2 is a Minecraft mod that changes the live visual style while Minecraft supplies the underlying rules. Oasis 3 Preview, introduced in June, instead accepts driving actions through an API and generates camera frames. Related names, different architectures and users. Decart ↗Decart ↗

Some of this frontier targets robots.

NVIDIA released Cosmos 3 Edge in July as a 4B-parameter world model. Its showcased driving simulation and robotics evaluations concern predicting physical consequences. They are relevant technical advances, but do not establish demand for consumer games. NVIDIA ↗

The economic distinction is simple. If you generate an asset or write code once, many players can reuse it. If a model synthesizes each player’s view continuously, playing creates ongoing inference cost. Hybrid products can choose where generation is worth that expense.

An evidence ladder, not a measured funnel. These are different products and populations; there are no implied conversion rates between the boxes.

Learn to read the denominator.

Games made can include unfinished experiments. Published games prove availability, not demand. Daily players measure activity, but a single reported snapshot does not show retention. Annualized revenue extrapolates a shorter period; it does not mean that cash has already arrived.

Retention asks a different question: of the people who started in the same period, how many returned a week or month later? A cohort is that shared starting group. If a new wave of visitors replaces everyone who left, overall user growth can hide weak retention.

What the market teaches us so far

Technical access is expanding. The named makers show that coding, 3D math and asset production are less exclusive barriers than before.

Human expertise changes shape. Selecting a good concept, recognizing a bad result and directing revisions become more consequential as implementation gets cheaper.

Distribution has not disappeared. A sports creator’s audience and a pediatrician’s clinics explain access to users that model capability alone does not supply.

More content may make selection more valuable. If game supply grows, trusted recommendations, remix communities and multiplayer social loops could become more important. That is an inference to test, not an established market law.

THE PRODUCT QUESTION

When everyone can access a strong model, what makes someone want to create, keep creating, and play here?

The opportunity

OpenGame could make a fragmented process feel continuous: bring an idea or existing agent-built game, refine it without breaking it, publish instantly, find players, and build on other people’s work. The lasting value could live in the project representation, reliability, community and discovery.

Its support for externally built games could be particularly useful: creators may already love their coding agent and primarily need a home, feedback and an audience.

The competitive pressure

General agents keep absorbing more of the build process. Specialized studios are learning the game workflow. Roblox brings an existing player network and monetization. A new platform needs a reason for a specific group to choose it even as all three improve.

“Better models will make this work” is an enabling thesis. “This group will build and play here repeatedly” is the product thesis that still needs evidence.

Six demonstrations that would teach you more than a polished pitch

01Watch a fresh creator build.

Start with a blank project. Measure time to the first playable result, how often help is needed, and whether the creator can make a specific second change.

This tests usability, not just the founders’ ability to operate the tool.

02Break something, then repair it.

Change movement, add multiplayer, or import an outside agent’s project. Show what survives and how a failed change is undone.

This exposes the value of the harness and the structure of the project.

03Remix a game and explain the result.

Change one mechanic in somebody else’s game. See whether credit, permissions and dependencies remain understandable.

This tests whether remixing is a real creative workflow.

04Follow the next ten creators.

Who comes back? What do they make the second time? Ask for a cohort, not only a total-project count.

This separates curiosity from a repeat creative habit.

05Follow the next hundred players.

Where did they come from, what did they play, and who returns after seven days? Separate creators testing their own games from other players.

This tests the player proposition and the discovery loop.

06Open the cost of one representative game.

Separate creation calls, repairs, hosting and any generation during play. Then consider many more players using the same game.

This reveals whether scale reuses earlier work or repeatedly pays for new inference.

The exciting change is that far more people can turn an idea into something you can actually play.

The next chapter will be written by products that help them make something worth playing again.
